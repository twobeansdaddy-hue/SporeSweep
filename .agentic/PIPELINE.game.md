# 게임 프로젝트 추가 절차 (game 프로필)

이 프로젝트는 게임이다. `PIPELINE.md`의 단계에 아래를 더한다.
승인 지점과 금지 규칙은 `PIPELINE.md`·`AGENTS.md`가 기준이고, 이 문서는 새 승인 지점을 만들지 않는다.
기획서·진행 상태 문서·실행 명령의 위치는 AGENTS.md "프로젝트" 절에 적혀 있다 (기본: `docs/PLAN.md`, `docs/STATUS.md`).

## 기획서가 기준이다
- 규칙·수치·화면·단계의 기준은 기획서다. 요청이 기획서와 다르거나 기획서에 없는 규칙을 정해야 하면
  코드를 먼저 바꾸지 않는다. 기획서를 어떻게 고칠지 보여 주고 확인을 받는다 (승인 지점 1: 요구사항이 모호할 때).
- 확인을 받으면 기획서와 코드를 같은 변경에서 고친다. 기획서에 적을 만큼 크지 않은 구현 결정은 진행 상태 문서에 적는다.

### 기획서 초안은 Antigravity(Gemini)에게 맡긴다
기획서를 새로 쓰거나 절 하나를 통째로 새로 써야 할 때(새 게임, 새 시스템, 콘텐츠 목록 확장) 초안을 맡긴다. 문장 몇 줄을 고치는 일은 네가 한다.
```
node tools/agentic/agy-research.mjs "<무엇을 쓸지 + 기획서 절대 경로 + 원하는 절 구성 + 지켜야 할 기존 결정>" --draft --tier deep
```
- 초안은 `.agentic/research/agy-draft-*.md`에 남는다. 기획서에 바로 옮기지 않는다.
- 네가 초안을 저장소의 실제 코드·기존 기획서와 대조해 읽는다: 서로 모순되는 규칙, 빠진 수치, 지금 코드로 만들 수 없는 항목, 한 번에 만들기에 너무 큰 범위를 짚는다.
  쓴 모델이 자기 초안을 검토하면 같은 맹점을 지나치므로, 이 검토는 agy에게 다시 맡기지 않는다.
- 초안과 네 검토 결과를 함께 보여 주고 기획서를 어떻게 고칠지 확인을 받는다 (위 승인 지점 1). 초안의 "## 미확인"은 사용자가 정할 항목이다.
- 종료 코드 75면 네가 직접 쓴다. 조사가 필요한 부분만 `researcher` 서브에이전트에 맡긴다.
- 확정된 기획서를 구현 단위(파일·순서·테스트)로 쪼개는 일은 네 몫이다. 초안이 구현 방법을 적었더라도 따르지 않아도 된다.

## 1단계에 더하는 것: 무엇을 바꾸는 요청인가
`--state`에 아래 분류를 함께 적고, 분류에 맞는 확인을 뒤 단계에서 한다.

| 분류 | 예 | 꼭 하는 확인 |
|---|---|---|
| 규칙 | 판정, 이동, 전투, 진행 저장 | 테스트 (같은 입력·같은 시드면 같은 결과) |
| 수치 | 속도, 가격, 확률, 보상, 난이도 | 조정 값 파일에서만 바꾼다. 이전 값 → 새 값과 이유를 보고한다 |
| 화면·조작·연출 | 화면 배치, 입력, 카메라, 효과, 소리 | 4-1단계 실행 확인 |
| 콘텐츠 | 맵, 레벨, 대사, 아이템 목록 | 데이터 검증(있으면)과 4-1단계 실행 확인 |
| 에셋 | 그림, 소리, 글꼴 | 출처·라이선스 기록, 4-1단계 실행 확인 |
| 플랫폼 | 결제, 광고, 순위표, 저장 위치, 스토어 | 5단계 고위험 확인 |

## 4단계에 더하는 것
- 돈이 드는 생성(음성·음악·이미지 생성 API 등)은 실행 전에 무엇을 몇 번 만들지 알리고 승인을 받는다 (승인 지점 4와 같이 다룬다).
- 에셋을 새로 만들거나 들여오면 출처, 라이선스, 만든 방법(도구·명령)을 프로젝트의 에셋 기록 문서에 적는다. 문서가 없으면 진행 상태 문서에 적는다.
- 프로젝트의 경고 검사 명령이 있으면 테스트와 함께 돌리고 경고 0을 지킨다.

### 에셋을 어디서 구하나
필요한 에셋마다 아래 순서로 고른다. 어느 경로든 AGENTS.md game 구역의 "다른 게임과 에셋" 규칙(출처·라이선스 기록, 실존 인물·다른 게임 IP 금지)을 따른다.

| 종류 | 먼저 볼 곳 | 비용 | 비고 |
|---|---|---|---|
| 실사 3D 스캔·표면 재질·데칼 | Quixel Megascans (Fab) | 에셋별 확인 (무료로 공지됨) | 받기 전에 그 에셋의 가격과 Fab 라이선스의 현재 문구를 확인한다. 계정 로그인과 약관 동의는 사용자가 한다 |
| 그림(컨셉 아트, 텍스처, 스프라이트) | 집 PC의 이미지 생성 서버 | 무료 | 아래 "집 PC" 절 |
| 많은 양의 글(대사 변주, 아이템 설명, 번역 초안) | 집 PC의 로컬 LLM | 무료 | 아래 "집 PC" 절. 결과는 초안이고, 게임에 넣기 전에 네가 읽고 고른다 |
| 음성·효과음·음악 | 프로젝트의 생성 스크립트 (ElevenLabs 등, `env-run.mjs`로 실행) | 유료 | 실행 전 승인 (위 "돈이 드는 생성") |

- Megascans: Fab의 상품은 무료일 수도 유료일 수도 있다. 에셋 페이지에서 가격을 확인하고, 유료면 "돈이 드는 생성"과 같이 승인을 받는다. 모델이 요청에 맞는 것을 고르지 못하면 후보 이름과 Fab 주소를 사용자에게 보여 주고 받아 달라고 한다. 에셋 기록 문서에는 에셋 이름, Fab 주소, 받은 날짜, 라이선스 이름을 적는다.
  Megaplants(식생)는 Unreal Engine 전용이라고 안내돼 있으므로 다른 엔진 프로젝트에는 쓰지 않는다.
- 생성한 에셋은 만든 도구·모델 이름·프롬프트(또는 워크플로 파일 경로)·시드를 에셋 기록 문서에 적어 다시 만들 수 있게 한다. 모델 라이선스가 상업 이용을 막으면 출시용 에셋에 쓰지 않는다.
- 용량이 큰 에셋(그림·소리·3D)을 저장소에 넣을 때 프로젝트가 Git LFS를 쓰는지 먼저 확인한다. 쓰지 않는데 큰 파일을 많이 넣게 되면 넣기 전에 사용자에게 알린다.

### 집 PC (이미지 생성 서버와 로컬 LLM)
주소·포트·켜고 끄는 방법은 프로젝트가 아니라 사용자 전역 설정(`~/.claude/CLAUDE.md`의 "집 PC" 절)에 있다. 그 절이 없거나 서버가 응답하지 않으면 이 경로는 없는 것으로 보고, 대신할 방법(유료 생성, 사용자가 직접 준비)을 사용자에게 묻는다.
- 이미지 생성 서버와 로컬 LLM은 **동시에 띄우지 않는다** (그래픽 메모리와 시스템 메모리를 함께 쓴다). 지금 어느 쪽이 떠 있는지 먼저 확인하고, 필요한 쪽이 아니면 전역 설정의 방법으로 바꾼다.
- 바꿀 때마다 모델을 다시 올리는 시간이 든다. 같은 종류의 일을 모아 한 번에 처리한다 (글 한 묶음 → 그림 한 묶음). 한 장씩 번갈아 시키지 않는다.
- 로컬 생성은 돈이 들지 않으므로 승인 없이 실행해도 되지만, 몇 개를 무엇으로 만들지는 실행 전에 한 줄로 알린다.
- 집 PC가 꺼져 있거나 다른 일에 쓰이고 있으면 켜거나 끄려 하지 말고 사용자에게 알린다.

### 4-1. 실행 확인 (분류가 화면·조작·연출, 콘텐츠, 에셋, 수치일 때)
테스트 통과만으로 끝내지 않는다. 게임을 실제로 띄워 바뀐 곳을 본다.
- AGENTS.md "프로젝트" 절의 실행·촬영 명령으로 띄우고, 바뀐 화면을 스크린샷으로 남겨 직접 확인한다
  (글자가 잘리거나 겹치지 않는지, 화면 밖으로 나가지 않는지, 멈추지 않는지).
- 수치를 바꿨으면 프로젝트의 균형 측정·시뮬레이션 명령이 있을 때 다시 돌리고 바뀐 값을 본다.
- 띄울 수 없으면(기기·엔진 없음, 헤드리스에서 안 뜸) 지어내지 않는다. "실행 확인 못 함"과 이유를 8단계 보고에 적는다.
- 네가 띄워 본 것은 사람의 플레이가 아니다. 조작감·재미·난이도는 "사람이 아직 플레이하지 않음"으로 남긴다.

## 5단계에 더하는 것: 판정과 상관없이 승인을 받는 변경
- 저장 데이터 형식을 바꿔 기존 저장을 못 읽거나 다르게 읽게 되는 변경
- 실제 돈이 오가는 것: 인앱 결제, 가격, 광고 보상, 유료 재화의 확률·지급량
- 스토어에 올라가는 것: 빌드 업로드, 스토어 문구·이미지, 연령 등급 관련 내용

## 7단계에 더하는 것
완료 게이트와 함께 실행 확인 판정을 받는다.
```
node tools/agentic/decide.mjs play-check --state "<변경 요약 + 실행 확인 방법과 결과 + 사람 플레이 여부>"
```
- `verdict.run_missing`이 참이면(플레이어가 보는 것이 바뀌었는데 실행 확인 근거가 없음) 4-1단계를 하거나, 못 한 이유와 함께 미확인으로 보고한다.
- `fallback: true`이거나 `uncertain`이면 네가 직접 판단한다.

## 8단계 보고에 더하는 것
- 실행 확인: 쓴 명령과 스크린샷 경로, 또는 "실행 확인 못 함"과 이유
- 사람 플레이: 했으면 누가·무엇을, 아니면 "사람이 아직 플레이하지 않음"
- 실기기: 시뮬레이터·에뮬레이터·데스크톱에서만 봤으면 "실기기 미확인"
- 바꾼 수치: 이전 값 → 새 값
- 에셋: 새로 넣은 에셋의 출처(Megascans / 집 PC 생성 / 유료 생성 / 직접 제작)와 기록한 문서
- 기획서 초안을 맡겼으면: 초안 파일, 네가 짚은 문제, 사용자가 정한 것
